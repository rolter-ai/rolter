The dashboard is the control plane's web UI. It is served by `rolter-control` on the same port as the API (`4001` by default) and works fully offline: it ships no runtime fonts, scripts or images from a CDN.

## Signing in

Open the control plane's address in a browser. You will see one of three things:

- **A password form** — the deployment has local accounts. Use the e-mail and password an administrator created for you, or the ones you chose when accepting an invitation link.
- **"Continue with …" buttons** — the organization registered an identity provider ([Single sign-on](/security/single-sign-on)). Password sign-in may be turned off alongside them.
- **An e-mail-only prompt** — the control plane is running in *open mode* with no admin token and no accounts. Anything you enter opens the dashboard; there is no session to protect. This is meant for a first local run only.

Your session is re-checked every time the dashboard loads. If it has expired, you are returned to the sign-in screen with a note saying so rather than a page full of failed requests.

The language switcher sits at the bottom of the rail, and on the sign-in card, so you can pick English or Russian before you have an account.

## The left rail

Everything lives under one of these groups. Screens you cannot read with your role are hidden; superadmin-only screens are hidden for everyone else.

| Group | What is inside |
|---|---|
| **Playground** | Send chat, embedding, image, audio or realtime requests through the gateway with one of your virtual keys. |
| **Observability** | Dashboard (traffic, spend, latency, error rate), LLM Logs, MCP Logs, Connectors, Logs Settings. |
| **Models** | Model Catalog, Providers, Provider Groups, Budgets & Limits, Routing Rules, Complexity Router, Circuit Breaker, Pricing Overrides, Model Settings. |
| **MCP Gateway** | MCP Catalog, Library, Tool Groups, Auth Sessions, OAuth Grants, MCP Settings. |
| **Plugins** | Webhook plugins in the request/response pipeline. |
| **Alerting** | Channels, Rules, History. |
| **Governance** | Virtual Keys, Users, Teams, Business Units, Customers, User Provisioning (SCIM), Single sign-on, Roles & Permissions, Access Profiles, Audit Logs. |
| **Guardrails** | Rules and providers for content, PII and safety checks. |
| **Cluster Config** | The gateways that poll this control plane. A gateway appears once it identifies itself, which needs `ROLTER_NODE_ID` or `HOSTNAME` set in its environment. |
| **Adaptive Routing** | Live scores from gateways on the adaptive strategy, and its settings. |
| **Prompt Repository**, **Skills Repository** | Versioned prompt templates and agent skills shared across the org. |
| **Settings** | Client settings, compatibility, the effective config viewer, security, your own virtual keys, performance tuning, feature flags. |

The search box at the top of the rail filters the entries by name.

## The scope switcher

Most screens show data for one **organization → team → project** chain. Open the account menu at the bottom of the rail to change any of the three, create a new one with the **+** button, or delete the selected one. The choice is remembered per browser; a fresh browser starts on the first organization you belong to.

Screens that are deployment-wide (feature flags, security, performance, cluster) ignore the scope.

## What a disabled control means

A greyed-out **Add**, **Delete** or toggle carries a tooltip naming the role the action needs (for example *Requires the Admin role*). The dashboard asks the control plane what your account may do and disables the rest up front, instead of letting you click and read a "forbidden" error afterwards. See [Roles and permissions](/security/rbac).

## Refresh and live data

The refresh button in every screen header re-reads everything on the screen. Screens that stream (LLM Logs, MCP Logs, Adaptive Routing) update on their own and show when they last did.

## Reading structured output

Anywhere the dashboard shows a payload — a request or response body in LLM Logs and MCP Logs, an audit entry's detail, the effective config, a model's config preview, the collector document, a copy-as-code snippet — it renders in a shared code block: syntax highlighted for its language, scrollable sideways rather than wrapped mid-token, reachable with the Tab key, and with a copy button in its corner. Highlighting is bundled with the dashboard, so it works with no internet access.

A very large payload is shown without colour rather than kept waiting for it.

## Markdown in the Playground

Model replies render as markdown: headings, lists, tables, inline code, and fenced code blocks highlighted per their language tag with a copy button of their own. Use the **¶** button in the column header to switch to raw output when the question is exactly what the model emitted, including stray delimiters and whitespace.

Replies are never treated as markup. HTML tags in a reply show as the characters they are, and an image in a reply is listed by its alt text instead of being fetched — nothing in a model reply causes the dashboard to reach the network.

## On a phone or a tablet

| Screen width | Navigation |
|---|---|
| Below 768 px | The rail is a drawer. Open it with the **☰** button in the screen header; close it with the scrim, the Escape key, or by picking a screen. |
| 768 – 1023 px | The rail starts folded to icons. Hover or focus an icon for its name; the collapse toggle expands it. |
| 1024 px and up | The full rail, collapsible, and resizable by dragging its right edge. The width you choose is remembered. |

Tables that are wider than the screen scroll inside their own frame, and forms that open as side sheets take the full width on a phone.

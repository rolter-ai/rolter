Environment variables override their corresponding `rolter.toml` values, and CLI flags override both. Use environment variables for secrets and for anything that changes between deployments — such as ports, database URLs, and provider API keys — so you can keep a single `rolter.toml` across environments without embedding sensitive values in it.

`--help` lists the variable behind each flag as `[env: NAME]` but never prints the value of a secret or a URL that can carry a password: the admin and internal tokens, and the database, Redis, ClickHouse, snapshot, admin and gateway URLs. It is safe to run in an environment that has them set, and to paste into an issue.

## Gateway variables

These variables control the gateway process (`rolter-gateway`).

| Variable                     | Purpose                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ROLTER_CONFIG`              | Path to the configuration file. Defaults to `rolter.toml` in the current directory, which may be missing (the gateway then starts with an empty config). A path set here or with `--config` must exist: the gateway refuses to start without it. A blank value counts as unset.                                                                                                                                                                                                                       |
| `ROLTER_CHECK_ROLE`          | Which process `rolter check` validates the environment of: `control` (the default, every rule) or `gateway` (only the rules that apply to a data-plane pod). The same as `--role`. The Helm chart passes it to each preflight init container.                                                                                                                                                                                                                                                         |
| `ROLTER_HOST`                | Listen host. Overrides `[server] host` in `rolter.toml`. `rolter easy-up` binds its gateway to it as well, and its control plane unless `ROLTER_CONTROL_HOST` is set, defaulting to `127.0.0.1`. The published image's default command passes `--host 0.0.0.0` so its published ports answer; with no `ROLTER_ADMIN_TOKEN` easy-up then refuses to start unless `ROLTER_ALLOW_OPEN_MODE=1`.                                                                                                           |
| `ROLTER_PORT`                | Listen port. Overrides `[server] port` in `rolter.toml`.                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `ROLTER_KEY_PEPPER`          | Secret mixed into virtual-key digests. Keeps plaintext keys out of gateway memory; a leaked digest is useless without it. Overrides `[server] key_pepper`.                                                                                                                                                                                                                                                                                                                                            |
| `ROLTER_CA_BUNDLE`           | Path to a custom CA certificate bundle in PEM format for TLS verification of upstream providers.                                                                                                                                                                                                                                                                                                                                                                                                      |
| `ROLTER_SNAPSHOT_URL`        | Control plane snapshot endpoint URL (e.g. `http://control:4001/internal/snapshot`) used by the gateway to hot-reload configuration in database mode.                                                                                                                                                                                                                                                                                                                                                  |
| `ROLTER_SNAPSHOT_POLL_SECS`  | Interval in seconds between gateway snapshot polls. Default `5`. Set the same value on the control plane: it does not poll, but the Playground sizes its wait for a freshly minted key from it.                                                                                                                                                                                                                                                                                                       |
| `ROLTER_ADMIN_URL`           | Control plane management URL used when the gateway proxies `/admin/*` management traffic to a co-hosted control plane.                                                                                                                                                                                                                                                                                                                                                                                |
| `ROLTER_SEMANTIC_MODEL_ROOT` | Directory every [local classifier](/security/semantic-guard-policies#local-classifier) model must resolve under. Overrides `[semantic_guards] model_root`; the gateway's `--semantic-model-root` flag overrides it. Read once at start: a snapshot never changes it. A blank value counts as unset; a value that is not UTF-8 refuses startup. With no root from any source, the gateway logs that model files are read unconfined.                                                                   |
| `ROLTER_GUARDRAIL_TOKEN`     | Bearer token used for webhook authentication with external guardrail services when configured via `token_env`.                                                                                                                                                                                                                                                                                                                                                                                        |
| `ROLTER_PLUGIN_TOKEN`        | Bearer token sent to external plugin endpoints when plugin authorization uses `token_env`.                                                                                                                                                                                                                                                                                                                                                                                                            |
| `OPENROUTER_HTTP_REFERER`    | HTTP-Referer header value attached to outbound OpenRouter requests for ranking/attribution.                                                                                                                                                                                                                                                                                                                                                                                                           |
| `OPENROUTER_X_TITLE`         | X-Title header value attached to outbound OpenRouter requests for app name attribution.                                                                                                                                                                                                                                                                                                                                                                                                               |
| `CLICKHOUSE_URL`             | ClickHouse HTTP interface URL, e.g. `http://localhost:8123`. Read by **both** the gateway (which writes request, usage and cost rows) and the control plane (which reads them back for the dashboard), so set it on both. A `[logging] clickhouse_url` in the gateway's own config file wins over it; a gateway with neither inherits the control plane's value from `/internal/snapshot`. Leave it unset everywhere and the Usage, Costs and Logs screens stay empty however much traffic is served. |
| `ORT_DYLIB_PATH`             | Only for a gateway built with the `onnx` feature: the ONNX Runtime shared library (`libonnxruntime.so`, 1.22 or newer) that runs `onnx/1` [local classifier](/security/semantic-guard-policies#onnx-models) models. Unset, the library is looked up on the system library path. Read when the first ONNX model is loaded.                                                                                                                                                                             |

## Control plane variables

These variables control the control-plane process (`rolter-control`), which manages the dashboard, management API, and config propagation.

| Variable                                  | Purpose                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `ROLTER_CONTROL_HOST`                     | Listen host for the control-plane HTTP server. Default `127.0.0.1`, or `ROLTER_HOST` under `rolter easy-up`. Inside a container, set `0.0.0.0` so a published port reaches it. A non-loopback host with no `ROLTER_ADMIN_TOKEN` refuses to start unless `ROLTER_ALLOW_OPEN_MODE=1`.                                                                                                                                                                                                                                                                                                        |
| `ROLTER_CONTROL_PORT`                     | Listen port for the control-plane HTTP server. Default `4001`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |

| `ROLTER_SMTP_URL`                         | Mail relay that invitation links are emailed through: `smtp://[user:password@]host[:port]` (STARTTLS when offered; `?tls=required` insists) or `smtps://host`. Can carry a password, so keep it in a secret. Unset (the default) means invitations are not emailed and the link is only returned to the admin. Held to the egress policy. See [Emailing invitations](/security/rbac#emailing-invitations).                                                                                                                                                                                 |

| `ROLTER_GATEWAY_URL`                      | Base URL of the data-plane gateway (default `http://localhost:4000`) used by the control plane to reverse-proxy dashboard Playground requests.                                                                                                                                                                                                                                                                                                                                                                                                                                             |

A blank value counts as unset.                                                                                                                                                                                                                   |
| `ROLTER_ALLOW_OPEN_MODE`                  | Boolean flag allowing the control plane to serve an unauthenticated management API on a non-loopback address when `ROLTER_ADMIN_TOKEN` is unset.                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `ROLTER_INTERNAL_ADDR`                    | Address to bind a dedicated socket for `/internal/*` routes (e.g. `127.0.0.1:4002`), separating internal traffic from the public/admin surface.                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `ROLTER_INTERNAL_TOKEN`                   | Bearer token required for `/internal/*` endpoints when separated from `ROLTER_ADMIN_TOKEN`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `ROLTER_CORS_ALLOW_ORIGINS`               | Comma-separated list of origins allowed for CORS preflight requests on the control-plane management API.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `ROLTER_SESSION_PEPPER`                   | Secret pepper mixed into the stored digests of sign-in sessions, invitation links, SCIM tokens and MFA recovery codes, like `ROLTER_KEY_PEPPER` for virtual keys, and into the failed-login throttle's Redis keys. Changing it, or setting it on a deployment that ran without one, ends every session and voids open invitations, SCIM tokens and recovery codes. `rolter init` generates it, and `rolter check` warns while it is unset. |
| `ROLTER_MFA_ISSUER`                       | Issuer name an authenticator app shows beside the account during TOTP setup (default `rolter`). Set it to tell several deployments apart.                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `ROLTER_UI_DIR`                           | Filesystem path to the built UI assets served by the control plane. Default `ui/dist`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `ROLTER_UI_DOCS_BASE_URL`                 | Base URL of the documentation site the dashboard deep-links into, e.g. `https://docs.example.com`. Unset by default, which suppresses every documentation link in the dashboard — see [Documentation links](/deployment/documentation-links).                                                                                                                                                                                                                                                                                                                                              |
| `ROLTER_UI_OTEL_ENDPOINT`                 | OpenTelemetry OTLP/HTTP traces endpoint (e.g. `http://localhost:4318/v1/traces`) injected into the dashboard for browser tracing. | `ROLTER_LOGIN_MAX_DELAY_MS`               | Ceiling on the delay added to a rejected sign-in. | `ROLTER_LOGIN_TRUST_FORWARDED_FOR`        | Count failures against the `X-Forwarded-For` client instead of the socket peer. ### Sizing the connection pool

One pool serves **everything** the control plane does: `/internal/snapshot` — which every gateway in your fleet polls — plus the whole dashboard CRUD surface, SCIM, SSO, MCP, and the RBAC guard's per-request membership lookups. Left too small, that budget silently becomes an acquire-timeout queue.

Size `ROLTER_DB_MAX_CONNECTIONS` against your **database's** `max_connections`, not against gateway count:

```text
ROLTER_DB_MAX_CONNECTIONS × (control replicas)  <  PostgreSQL max_connections − headroom
```

Leave headroom for migrations, backups, and any other client of the same database. Gateway count is a weak input here — snapshot polls are short and answer `304 Not Modified` most of the time, so a large fleet does not need a proportionally large pool.

<Tip>
  Raise the ceiling when all three of these hold at once: `rolter_db_pool_acquire_ms` shows waits, `rolter_db_pool_idle` sits at zero, and `rolter_db_pool_connections` is pinned to `rolter_db_pool_max`. That combination means the ceiling is the bottleneck. Acquire waits *without* a pinned pool mean the database itself is slow, and a bigger pool will make that worse.
</Tip>

Keep `ROLTER_DB_ACQUIRE_TIMEOUT_SECS` bounded. It is what turns pool exhaustion into a fast, attributable error instead of an opaque stall that looks like a database outage.

### Bounding writes

Nothing waits forever on the control plane's database. `ROLTER_DB_LOCK_TIMEOUT_SECS` (default `10`) and `ROLTER_DB_STATEMENT_TIMEOUT_SECS` (default `30`) are set on every pooled connection, so a write that sits behind another transaction's row lock, or a statement that runs away, ends with a `504` in the usual error envelope and the code `store_timeout`. `ROLTER_REQUEST_TIMEOUT_SECS` (default `60`) is the outer bound for everything else a request can wait on; it answers `504` with the code `request_timeout`. The dashboard learns this bound from the page the control plane serves and gives up on a call 5 seconds after it, so a connection that never answers at all ends with the same message instead of a spinner that never stops. Keep the three in that order, lock below statement below request, so the database answers first and names the cause. Schema migrations run on a connection without the two database bounds, since an index build can legitimately outlast them.

### Throttling failed sign-ins

`POST /api/v1/auth/login` is an unauthenticated endpoint that runs an argon2id verification for every request. That cost is what makes password guessing expensive — and it is also what makes an unthrottled login endpoint a cheap way to saturate the control plane's CPU. Rolter therefore counts rejected sign-ins and refuses further ones **before** any password work happens.

Two counters run independently:

- **Per account.** `ROLTER_LOGIN_MAX_FAILURES` rejected attempts inside `ROLTER_LOGIN_FAILURE_WINDOW_SECS` lock the account for `ROLTER_LOGIN_LOCK_SECS`. Each further failure doubles the lock, up to `ROLTER_LOGIN_MAX_LOCK_SECS`.
- **Per client address.** `ROLTER_LOGIN_IP_MAX_FAILURES` covers spraying one guess across many accounts, which a per-account counter never catches. The budget is higher because one office egress address is a whole floor of legitimate typos.

Before the lock engages, each rejected attempt is answered a little more slowly than the last, up to `ROLTER_LOGIN_MAX_DELAY_MS`. A locked attempt is answered `429` with a `Retry-After` header, so a client waits rather than polling.

Every counter is keyed on the _submitted_ address, never on an account that was found, so throttling reveals nothing about which addresses are registered. Failed attempts, engaged locks and sign-ins that follow one are written to the audit log, and `rolter_control_login_attempts` counts them by outcome so a credential-stuffing run is visible on your dashboards.

<Note>
  **Locks always expire on their own.** A lock is a timer, not a flag an administrator has to clear — a lock somebody else can *set* would be a way to shut a colleague out of their own account. The worst an attacker achieves is a bounded outage capped by `ROLTER_LOGIN_MAX_LOCK_SECS`.
</Note>

**Where the counters live.** With `ROLTER_REDIS_URL` set, they live in Redis and every control-plane replica counts against the same budget. Without it they are process-local, which is correct for a single-node deployment: with N replicas and no Redis, each replica holds its own budget, so an attacker effectively gets N times the allowance. The control plane logs which mode it is in at startup.

<Warning>
  Behind a reverse proxy, every request reaches Rolter from the proxy's address, so the per-address budget becomes a *shared* one. Either raise `ROLTER_LOGIN_IP_MAX_FAILURES` or set `ROLTER_LOGIN_TRUST_FORWARDED_FOR=1` — but only set it if every request really does arrive through a proxy that overwrites `X-Forwarded-For`. An unverified forwarded header hands an attacker an unlimited supply of budgets *and* the ability to spend somebody else's. The per-account counter is unaffected either way.
</Warning>

<Warning>
  `ROLTER_KEK` is the most sensitive secret in your Rolter deployment. Any party who holds this key can decrypt every stored provider credential. Generate a strong value before first run and store it in a secrets manager:

```bash
openssl rand -hex 32
```

Once the database is populated, rotating this key requires re-encrypting all stored credentials. Treat it with the same care as a private CA key.

</Warning>

### Update check

The control plane asks `https://api.github.com/repos/rolter-ai/rolter/releases/latest` once at boot and every six hours whether a newer **stable** release exists, and serves the answer from [`GET /api/v1/version`](/api/version) so the dashboard footer can show a small _v0.2.0 available_ hint. The `rolter` CLI runs the same check beside whatever command you start, caches the answer in `~/.cache/rolter/update-check.json` for 24 hours, and prints one line to stderr:

```text
rolter 0.1.0 is installed; 0.2.0 is available: https://github.com/rolter-ai/rolter/releases/latest
```

What the check does and does not do:

- One request, a 5-second timeout, carrying nothing but a `User-Agent: rolter/<version>` header. No installation id, no configuration, no credentials.
- It never blocks a command, never changes an exit status, and never logs above `debug` when it fails. Offline, rate-limited and malformed answers all look the same: no hint, no notice.
- The CLI remembers a failed attempt too: a host that cannot reach `api.github.com` tries once a day, not on every command, and keeps showing the last release it learned of.
- Pre-release tags are never advertised. A pre-release build (`0.2.0-rc.1`) is told about the stable release it precedes; a build newer than the latest release stays quiet.
- `rolter easy-up` supervises both planes in one process and prints the notice once.

`ROLTER_UPDATE_CHECK=false` (also `0`, `no`, `off`) turns it off for both the control plane and the CLI. Set it in an air-gapped deployment, or in any script that must make no outbound call at all; the footer then shows the running version alone and `/api/v1/version` reports `"enabled": false`.

## Provider key variables

Provider credentials are not hard-coded variable names — you choose the name and reference it in `rolter.toml`. Any variable name you set in a provider's `api_key_env` field becomes a provider key variable for that deployment.

A variable that holds a deployment secret (`ROLTER_KEK`, `ROLTER_DATABASE_URL`, `PGPASSWORD`, any other `ROLTER_` name except `ROLTER_GUARDRAIL_TOKEN`) cannot be a provider key. The dashboard refuses it with a `400`. A gateway that meets such a name in a snapshot serves that provider without a credential and lists the row on `/config/problems`; a file config that names one fails validation, and `rolter-seed --import` stops before it writes anything. The same names are not sent as a guardrail webhook or plugin credential either.

```toml
[[providers]]
name = "openai"
kind = "openai"
api_base = "https://api.openai.com"
api_key_env = "OPENAI_API_KEY"   # Rolter reads os.env["OPENAI_API_KEY"]

[[providers]]
name = "anthropic"
kind = "anthropic"
api_base = "https://api.anthropic.com"
api_key_env = "ANTHROPIC_API_KEY"
```

Common provider key variables in use:

| Variable             | Typical provider |
| -------------------- | ---------------- |
| `OPENAI_API_KEY`     | OpenAI           |
| `ANTHROPIC_API_KEY`  | Anthropic        |
| `OPENROUTER_API_KEY` | OpenRouter       |
| `TOGETHER_API_KEY`   | Together AI      |
| `GROQ_API_KEY`       | Groq             |

<Tip>
  Always use `api_key_env` rather than writing your provider key inline in `rolter.toml`. Inline keys end up in version control, Docker image layers, and config backups. With `api_key_env`, your `rolter.toml` is safe to commit; only the environment running the gateway ever sees the actual key.
</Tip>
